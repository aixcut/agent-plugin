# 字幕工作流

生成、编辑、分段、样式化并验证字幕，让字幕与实际语音时序一致。

## 先确定字幕来源

| 视频类型 | 来源 | 动作 |
| --- | --- | --- |
| 旁白视频 | 已放置配音音频的转写 | 确认音频 `transcript_status=available`，执行 `aixcut_caption(action="regenerate")`，再回读 |
| 口播视频 | 语音轨转写 | 从语音轨派生字幕 |
| 用户提供文案 | 用户文案 | 按文案对齐画面或配音 |

视觉素材通常没有可用转写。已保存的配音脚本不等于转写完成，不能把脚本当作 ASR 结果。

## 字幕与视觉标注分轨

字幕轨只承载口语字幕或用户提供的字幕文案。配料标注、箭头、圆圈、标题、花字、贴纸、Motion Graph 属于独立视觉轨道上的视觉元素，不写进字幕轨，也不能因为字幕里出现了同样的词，就当作视觉包装已经完成。

## 最短路径

1. `aixcut_read(view="captions")` 读取现有字幕与模式，同时读取 `speech` 或 `timeline` 确认配音已放置。
2. 旁白视频重新读取音频源的 `transcript_status`，只有 `available` 时才重建；等待中的状态先等后读，如实报告缺失或失败。
3. 再读 `captions`，确认条数、首尾时间和文本来自转写。
4. 报告完成前确认字幕轨没有动效、画面文字或其他标注片段。

## 时序与断句

- 字幕对齐语音，不只对齐画面切点。
- 每条最多两行；长句在标点或语义边界拆分。
- 拆分后相邻字幕不留空隙、不重叠。
- 逐词高亮动画必须在一次 `set` 或 `add` 中批量创建：每个 item 自带 `duration_ms` 和 `highlight_ranges`，当前段的结束时间直接取下一段起点；不要逐词创建后再循环修补时间。
- 配音位置变化时同步重建或重新对齐字幕。

## 可读归并

服务端派生字幕会合并同一说话人、同一媒体、连续源语音中的相邻转录碎片；视觉切点不能阻止同一句话归并。不要因为原始转写分成多行就再次拆开。

- 派生后只读回一次，优先修复仍然短于 300ms、不可读或明显截断语义的残留碎片。
- 所有残留修复放在一次批量调用中，不逐条循环 merge。
- 带计划范围校验时，`delete_refs` 必须写实际待删除的 caption clip refs，绝不写 `timeline_id`；结构 revision 变化后重新读取字幕引用，不复用旧引用。

## 写入规则

- 整轨替换用 `set`，追加用 `add`；创建时每条字幕的 `start_ms`、`duration_ms`、`style`、`x`、`y` 和 `highlight_ranges` 都放在对应 item 内。对已落库的多条字幕做统一样式、高亮或删除时，直接用 `targets: [...]` 在一次原子调用内完成（`style`、`highlight`、`delete` 均支持 `target` 或 `targets`），不要逐条循环。
- 每次结构写入使用新的幂等键，写后回读；位置编辑必须使用最新引用。
- 字幕写入会切换到手动模式，浏览器不再按转写自动重建。`aixcut_caption(action="mode", mode="auto")` 只恢复自动跟随标记，不会重建字幕，切换前先征得用户同意。
- 重建是独立的 `regenerate` 操作，只在源转写 `available` 时使用。
- 不要重建仍然有效且与当前配音一致的字幕轨。

## 边界

- 不要用普通文字 Tool 编辑字幕。
- 自动派生失败是警告：如实报告，不声称已生成字幕。
- 转写等待中不要重渲染配音或重新导入音频；保留 `MCP_CAPTION_TRANSCRIPT_PENDING` 等错误状态。
- 不要为修改字幕措辞而编辑转写；转写只修正识别错误。
